## How To Use

Each numbered row is one executable scenario pack. A pack may contain several read/options/PDF/restore endpoints for one resource family; execute every endpoint named in the row, not just the SPA happy path.

Use the following checks for every applicable row:

| Code | Required check |
|---|---|
| `AUTH` | Signed-out access is rejected; expired session/password behavior is safe; no bearer token or browser storage credential is used. |
| `RBAC` | Allowed seeded role succeeds; a nearby non-owner role receives the expected 403 from the direct API, not only a hidden UI action. |
| `ROW` | Same-department, other-department, own-record, other-record, driver, vendor, and customer tenant boundaries are checked where the resource supports them. |
| `LIFE` | Valid and invalid status transitions, terminal-state immutability, reject/cancel/restore behavior, and stale-state behavior are checked. |
| `EFFECT` | Cross-module records, GL, inventory, document, outbox/listener, and chain-state effects are checked. |
| `NOTIF` | In-app notification recipient, unread/read behavior, toast, and action link are checked. |
| `DUP` | Rapid double-click, replayed HTTP request, queue/listener replay, and duplicate document/stock/GL effects are checked. |
| `FILE` | PDF, CSV, upload, download, MIME, ownership, and masked-sensitive-data behavior is checked where present. |
| `MOB` | Responsive behavior and touch target are checked on the ordinary mobile route where present. |
| `FLOOR` | Floor PWA layout, operator scope, high-contrast theme, and large touch targets are checked where present. |

Default per-row expectation is `AUTH + RBAC + ROW + LIFE + EFFECT + NOTIF + DUP`; the row calls out exceptions or additional checks explicitly. `NOT RUN` means no assertion has yet been made.
