# DSS full-scope audit — 2026-10-23

## Executive result

DSS now has a shared, read-only detector pipeline across approvals, cross-module handoffs, quality, receivables, payroll, production, maintenance, training, master data, and bill matching. Eleven detector families are registered. Every detector defaults to `shadow`; Decision Center shows only enabled `advisory` results. No detector performs a business write or bypasses an existing approval/workflow.

This is broad system coverage, not complete decision coverage: the decision inventory contains 33 decisions and eleven have partial detector coverage. High-risk decisions remain explicitly deferred where source data, ownership, or business policy is incomplete.

## Audit boundary

Reviewed the DSS engine, API routes/controllers, detector registrations, visibility rules, parameter trust boundaries, scheduled maintenance, Decision Center, sidebar permissions, role seeding, the approval filter registry/board, existing workflow services reused by detectors, and `docs/dss/00-discovery.md`, `01-decision-inventory.md`, and `FINDINGS.md`.

Verification used focused PostgreSQL-backed Laravel feature tests, SPA tests/typecheck, route parity, PHP lint, and diff checks. No production database, live role accounts, shadow history, or business-owner sign-off was available.

## Findings and fixes in this pass

### Closed in code

- Detector visibility now scopes at both permission and role level. Approver-bottleneck rows are restricted to the current step role; payroll, receivables, production, and preventive-maintenance outputs are restricted to their decision owners. Delegated approval roles remain recognized.
- Approval type tabs and API filter validation use the same user-specific `ApprovalTypeRegistry` options. Users cannot submit a hidden type filter. Existing feature tests cover role filtering and request validation.
- Disabled, shadow, unknown, expired, and unowned recommendations remain hidden from list, detail, and actions. The service rechecks ownership after locking before recording outcomes.
- A detector run newer than an open recommendation invalidates that old card until the detector reports it again. Pausing or changing detector/engine configuration expires open rows with an audit event. This prevents stale shadow results from resurfacing on promotion.
- New open recommendations get a rolling 26-hour validity window. Existing open rows receive a one-time backfill. Hourly runner outages therefore cannot leave indefinitely actionable cards.
- Detector runs use per-detector locks, bounded inputs, scan completeness, partial-run status, and complete-only disappearance reconciliation. Disabled detectors now log a skipped run. Incomplete scans do not expire unobserved results.
- User-visible detector parameters are allow-listed and type/bounds checked; unsupported `assisted` mode is rejected. Payroll and training summaries omit employee-level detail.
- Run logs are pruned after 90 days. JSONB owner-scope fields and detector freshness lookups have indexes.
- Fixed a clean-install PostgreSQL migration failure: JSON `=` comparison on a `json` column in migration 0495 now compares its text representation.
- Decision Center empty state surfaces coverage/engine state. Sidebar access follows the DSS decision-role matrix. The migration revokes legacy broad `dss.view` grants from every role outside that matrix, including employees, drivers, and maintenance technicians; the seeder test checks the full role set.

### Open risks requiring separate work

1. **Coverage is not yet calibrated.** No historical replay, production shadow review, sampled precision, role-by-role live QA, or agreed notification cap has been completed. Keep every detector in shadow until the Wave 1 precision bar and owner review in `02-plan.md` are met.
2. **DSS SQL timeout is per statement, not per detector.** PostgreSQL detection now runs in a transaction with a transaction-local `statement_timeout` from the configured budget. Multiple statements can still exceed the total budget; SQLite and non-SQL time still rely on the after-return check. A cumulative deadline or worker boundary remains, and the 300-second maximum sits close to the 310-second detector lock TTL.
3. **Several decision inputs remain semantically unsafe.** `F-01`, `F-02`, `F-03`, `F-05` through `F-11`, and `F-15` remain open in `FINDINGS.md`. Do not build supplier selection, inventory reorder recommendations, stock-out forecasting, or cash optimization on those fields until their owners resolve the listed semantics. Daily stock snapshots have no pre-2026-10-12 backfill; D01/D24/D28 historical signals need enough reconciled history first.
4. **No publisher or model-quality evaluation surface exists yet.** An admin-only activity summary now reports tracked opens, follow-ups, source-verified clearances, and recurrence. It does not measure reviews, precision, recall, value realized, or per-detector calibration. DSS still sends no notifications or digests; recorded outcomes are not evidence of model quality.
5. **The 26-hour window assumes the hourly DSS schedule.** A deliberately longer run cadence needs an explicit detector validity policy.
6. **The broad SPA route audit remains open.** DSS route middleware/parity is checked; this pass did not audit every non-DSS frontend route in the application.
