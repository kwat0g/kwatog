# HR Audit

Date: 2026-09-18
 
## Re-audit 2026-09-19

Current verdict: **open**. Profile-update encryption/list scope is current, but it does not close the HR workflow.

- Direct employee bank edits still bypass Finance approval; profile review mutations lack row scope and field validation.
- Employee restore still leaves the linked account disabled; salary basis/history, recruitment conversion, document cleanup, training assignment, position restore, and onboarding failure signaling remain under-tested or open.
- Full current classification: `RE-AUDIT-REGISTER-2026-09-19.md`.
Scope: `api/app/Modules/HR/` excluding `FinalPayService`/`SeparationService` internals (H2R doc).
Claims are **[confirmed]** (file:line/grep) or **[assumption/unverified]**.

---

## 1. Findings — highest severity

1. **Plaintext bank/gov data in profile-update requests + no row scope.**
   `ProfileUpdateRequest` casts `changes` to an array and migration 0121 stores plain JSON; a
   `bank_account_no` change is persisted **unencrypted** (and copied into `audit_logs` via
   `HasAuditLog`), unlike `Employee.bank_account_no`. `ProfileUpdateRequestService::listForReview()`
   has no owner/department scope and the route is gated only on `hr.employees.view` (held by dept
   heads), so plaintext bank numbers are company-wide readable. `financeApprove()` blocks the
   submitter but not the HR reviewer, so one user can clear both legs. **[confirmed]**
2. **Restore leaves the login disabled.** `EmployeeController::restore()` is a bare
   `$employee->restore()` (no service/transaction); `EmployeeService::delete()` had deactivated the
   linked account, so a restored employee stays locked out. **[confirmed]**
3. **Competence surfaces are self-only for department heads.** `EmployeeCompetenceScope` passes
   `departmentPermission: null`, so heads holding training/skill `manage` cannot manage their
   department (docblock claims department+self).
4. **Self-service home payslip bypasses publication policy.** `SelfServiceHomeService::latestPayslip()`
   hardcodes `status='finalized'` and ignores `error_message`, so an errored finalized payroll can
   appear on the home dashboard but 404 on download.
5. **Document restore orphans the file.** `EmployeeDocumentService::delete()` physically deletes the
   file then soft-deletes; `restore()` restores only the row → permanent 404.

## 2. Findings — employee/recruitment/onboarding

6. `EmployeeService::update()` never recomputes onboarding (create/recompute contract); list vs
   detail can disagree on the onboarding badge.
7. Employee-number race surfaces as a raw 500, not 422. Default-shift insert is not guarded against
   an existing assignment.
8. `EmployeeResource` masking tiers inconsistent: `canViewSensitive()` omits the `system_admin`
   override that `maskField()` grants.
9. `Employee.status` is still `$fillable` despite update() rejecting it (hardening incomplete).
10. `EmployeeStateMachine` allows `active → resigned/terminated/retired` directly, so any future
    caller bypasses the clearance/final-pay guards.
11. Onboarding default reminder audience includes `system_admin`, contrary to the exec-tier policy.
12. `UserProvisioningService` missing role is a 500; `AutoProvisionUserOnEmployeeHire` catches only
    two exception types, so other failures retry forever.

## 3. Findings — training/documents/skills/master data

13. **Training expiry "newest" is determined by id, not `completed_at`**, so a backfilled cert with a
    higher id suppresses alerts on the truly-newest record.
14. Deleting a `Training` (soft) leaves existing assignment lists rendering a null training name.
15. MIME validated only by extension (`mimes:`), no server-side sniff.
16. `EmployeeSkillService::assign` restores a trashed row then `fill()` without clearing stale
    `certified_by`/verification metadata.
17. `SkillService`/`TrainingService` read `(bool) $filters['active']`, so `?active=false` returns the
    inactive set; `DepartmentService` correctly uses `filter_var`.
18. `PositionService` doesn't normalize `direction` (`?direction=x` → 500) and doesn't lock before the
    case-insensitive title check.
19. `DepartmentService` cannot create a department with a head in one call (head must already belong).
20. Route permission drift: department list allows `hr.directory.view` but show/tree require
    `hr.departments.view`; three overlapping training/skill permission namespaces.
21. `EmployeeImporter` bypasses the case-insensitive position uniqueness check.

## 4. Finding — salary adjustment

22. `EmploymentHistory.approved_by` is set to the **requester**, not the approver; and there is no
    guard against two pending adjustments for the same employee (last approval silently overwrites).
23. `SelfServiceDocumentService` can issue a salary-certified COE (`with_salary`) with no extra
    permission.

## 5. Dead code / still-present

- Dead: `EmployeePropertyController`/`EmployeePropertyService`/`EmployeeDirectoryController` (routes
  commented; SPA still calls the dead property URLs → 404s); `position` in `EmployeeResource`.
- Still present from prior audits: `is_final_pay_deduction` never set by HR; leave-encashment only in
  FinalPay/year-end.
- No `TODO/FIXME` markers.
