# CRM Audit (price agreements, products, negotiation, inquiries)

Date: 2026-09-18
Scope: `api/app/Modules/CRM/` excluding the Sales Order chain (O2C doc) and complaint/8D
(Quality doc). Claims are **[confirmed]** (file:line/grep) or **[assumption/unverified]**.

---

## 1. Walkthrough

- **PriceAgreementService**: flat/tier pricing, active + date-window resolution, app-level overlap
  guard (no DB constraint). Used by `SalesOrderService::create/update`.
- **ProductService/Product**: catalog with `part_number`, optional `revenue_account_id`, archive
  guard when sales-order lines exist.
- **SalesOrderResponseService**: customer counter-offer (propose/accept/decline), accepted proposals
  rewrite SO lines and re-run the credit gate; B2B portal integration.
- **CRM routes**: sales orders, responses, complaints, products, price agreements.

## 2. Findings

1. **`crm.products.manage` and `crm.price_agreements.manage` are granted to no seeded role** — only
   `system_admin` via wildcard. Product and price-agreement create/update/delete endpoints (and the
   SPA create/edit routes) are dead for every business role. **[confirmed]**
2. **`Product.revenue_account_id` is API-unreachable** — fillable/cast/related and consumed by
   Delivery/Returns, but no request accepts it and no resource returns it; only a seeder sets it.
   The C-1 revenue override cannot be configured. **[confirmed]**
3. **Portal response-line ID fallback bypasses HashIDs.** `HashIdFilter::decode(...) ?? (int) $id`
   plus a request that only requires `string`, so a customer portal user can name lines by raw
   integer id. **[confirmed]**
4. **Orphaned leads/opportunities schema.** Migrations create `leads`/`opportunities` and seed
   `crm.opportunity.initial_probability`, but no model/route/service/enum exists; the migrations
   reference enums that were never created. `contact_inquiries.converted_to_lead_id` is never set.
5. **Inquiry inbox lacks the `feature:crm` gate** (it lives in the Landing module), so disabling CRM
   does not close the backend.
6. **`can_confirm` is assigned the same expression as `can_respond`** on `SalesOrderResource` and is
   unused in the SPA (dead/wrong).
7. **`is_open_to_customer_response` ignores an existing accepted response**, so a customer can keep
   filing proposals after accepting.
8. **Duplicate proposal items silently drop** (no dedupe of `sales_order_item_id`; apply keys by it).
9. **Accepted counter-offer writes `proposed_unit_price` directly**, bypassing `PriceAgreementService`
   (the only price write not through the resolver).
10. **Tier fallback gives a 1-unit order the lowest-tier (volume) price**; `pricing_method=""` is
    silently coerced to `flat`.
11. **Product `part_number` matching is inconsistent** (exact vs `strcasecmp`) and
    `unique:products,part_number` is case-sensitive under PG, so `ABC`/`abc` coexist while BOM
    treats them as the same sub-assembly. No FK to `items.code`.
12. **Product archive guard counts soft-deleted/cancelled sales orders**, so a product that ever
    appeared on an order can never be archived — yet `UpdateProductRequest` can set `is_active=false`
    freely (unguarded archive).
13. **`SalesOrderTransitionRejection` is write-only** — never read anywhere, `requested_by` hard-coded
    null, `reason_code` always `'illegal_transition'`.
14. **Notification failures on negotiation are swallowed to `Log::warning`** (silent outage).
15. **Duplicated pricing-tier validation** (request trait + service) and **duplicated response-item
    mapping** (two resources with a "keep in sync" comment).
16. **No CRM jobs/scheduled behavior** — no price-expiry sweep, stale-response reminder, or
    acceptance-callable events (no event on customer response/resolution).
