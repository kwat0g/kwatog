# Email audit findings

Date: 2026-10-20. Static findings only; reachability and runtime impact remain unverified. Fixes belong in separate functional/security changes, not the email-template work.

| ID | Finding | Evidence / impact | Follow-up |
|---|---|---|---|
| EF-001 | Local development mail initially could reach external SMTP | `.env` and `api/.env` contained AWS Mail Manager SMTP settings. Both now use `MAIL_MAILER=log`; SMTP values remain present but inactive. Horizon was restarted and its booted `mail.default` was verified as `log`. The shared-foundation branch redirects to `MAIL_TEST_TO` or fails closed. | Keep local mail on log or a verified sink; verify the deployed guard before any non-production send. |
| EF-002 | Company settings need owner verification | Shared foundation now requires `company.legal_name` and `company.address` instead of using fallback literals, uses the configured legal name when `email.brand_name` is empty, and makes other optional identity values settings-only. The local settings rows exist; sales inbox and VAT status match the old fallback strings. | Owner verifies brand, company, and contact settings before external send. Accountant reviews statutory fields. |
| EF-003 | Welcome/reset emails disclosed temporary passwords | Confirmed call paths: admin-created account welcome, HR employee onboarding, and HR password reset. Draft PR #273 replaces emailed passwords with short-lived, single-use SPA reset/setup links and tests legacy queued payloads. Its CI currently fails an unrelated array-mailer test that lacks the configured From header; rerun after EF-061 reaches its base. HR/security review remains required. |
| EF-004 | Customer/supplier decision emails used synchronous SMTP in services | Current main sends customer sales-order and supplier PO decisions with `Mail::send`; their background/transaction behavior depends on caller. Draft PRs #233 and #239 change these paths to queued mailables with `afterCommit()`. Payslip still uses `Mail::send` inside an already queued job; this does not block the web request, but provider failures can retry the job. Verify idempotency and failure handling before closing. |
| EF-005 | Generic emails vary in sensitivity but share one body path | `NotificationService` can queue `UserNotificationMail` with arbitrary caller title/message/link for opted-in notification types. | Classify runtime type keys and remove sensitive body details or restrict eligibility as a separate privacy/RBAC change. |
| EF-017 | Markdown email preheaders were dropped before reaching the HTML layout | Email views could provide `preheader`, but Laravel's shared `mail::message` component did not pass it into `mail::layout`; hidden preview text was absent from rendered messages. | Fixed in shared foundation PR #213 by forwarding the value; verified with shell and portal-email renders. |
| EF-018 | Shared email CSS blocked dark colors and forced 600px mobile overflow | Important light-mode styles overrode dark-mode media rules after CSS inlining, and the 600px table width exceeded a 390px viewport. | Fixed in shared foundation PR #213; browser previews verify responsive width and dark colors. Real email-client behavior remains unverified. |
| EF-020 | Dark-mode fallback links had low contrast | Browser preview showed rust-colored text links too dim against the dark email background. | Shared foundation PR #213 now uses a brighter dark-mode link color; browser screenshots rechecked. |
| EF-058 | SPA dependency audit blocked CI on two high-severity advisories | `npm audit --audit-level=high` flagged Vite 7.3.6 and `follow-redirects` 1.16.0 in the existing lockfile. | Lockfile fix is isolated in PR #271: Vite 7.3.7, `follow-redirects` 1.16.1, zero audit findings. |
| EF-061 | PHPUnit email tests lacked reserved test recipient and default sender | CI on PR #213 failed when the non-production guard rejected mail without `MAIL_TEST_TO`; the array transport also requires a From header. | Shared foundation now forces a reserved `.test` recipient, sender address, and sender name in PHPUnit. The fix is local and awaits a fresh CI run. |
| EF-116 | Demo seeder tests assert stale employee-account counts | PR #275 run `39582978903` failed two `DemoAccountSeederTest` assertions: the seeder produced 20 internal accounts while tests expected 18. This is unrelated to email behavior. | Fixed on PR #275 at `d7f76553`; the exact test file passed locally (4 tests, 16 assertions). GitHub has no check run for the new head yet. |
| EF-117 | Return-management delivery-date inputs used UTC instead of the Manila calendar date | Five minimum-date and submit-validation expressions used `new Date().toISOString().slice(0, 10)`, which can reject a valid date near Manila midnight. | Fixed in `fix/rma-manila-date-inputs` using existing `manilaIsoDate()`; focused Vitest (4 tests) and targeted ESLint passed. Draft PR #316. |
| EF-119 | Portal invitation screen still promised a temporary password after switching to setup links | Supplier and customer invite forms and success toasts described the retired temporary-password email, contradicting the one-time password setup link sent by `PortalAccessInvitationMail`. | Corrected in pushed commit `dd7a26d0` on PR #223: forms describe the setup link, success copy confirms queueing without claiming delivery. Targeted ESLint and `git diff --check` pass. PR head now matches; no checks are attached to the new head yet. |
| EF-120 | PHP amounts use ISO code while SPA uses peso symbol | E-002 desktop/mobile light/dark re-review showed `PHP 125,000.00`; the SPA's configured-currency formatter renders the same PHP amount as `₱125,000.00`. `CurrencyDisplayService` feeds API notices and transactional emails. | Fix in draft PR #319 maps configured `PHP` to `₱` while preserving other codes; focused unit tests and Composer audit pass locally. |
| EF-121 | Capacity-plan conflict list materializes full model rows before extracting one field | PHPStan flags `get()->pluck('scheduling_diagnostic')`; this loads complete planned work-order rows when only diagnostics are returned. | Fixed in draft PR #321 with query-level `pluck`; `CapacityPlanningServiceTest` passed (22 tests, 64 assertions). |
| EF-122 | NCR full-piece capture queried `WorkOrderOutput` from the wrong namespace | PHPStan flagged the unqualified class in `NcrService`. Current `origin/main` has the correct `App\Modules\Production\Models\WorkOrderOutput` import; rerun affected checks on the updated base before closing this finding. |
| EF-123 | Reconciliation accepted a legacy supplier shipment without an audit note | A supplier shipment without item quantities could be reconciled and redispatched without recording why, despite the existing regression test requiring HTTP 422. | Fixed in draft PR #322; the targeted `SupplierShipmentTest` case passed (1 test, 7 assertions). CI stops at the inherited EF-118 Composer audit before PHPUnit. This functional fix is separate from email code. |
| EF-090 | Training expiry alerts linked employees to an HR-only page and sent staff details without checking row access | Employee self-alerts linked to `/hr/employees/{id}`, while configured staff recipients were not checked for employee/training permissions or employee scope. | Fixed in draft PR #301 with separate self/staff payloads, effective permission checks, `EmployeeCompetenceScope`, and a regression test. HR/legal/data-protection review remains required. |
| EF-113 | Unset `APP_ENV` bypassed the non-production mail guard | `config/app.php` defaulted a missing environment to `production`, so a local install without `APP_ENV` could skip recipient redirection if switched from the safe `log` mailer. | Shared foundation now defaults an unset environment to `local`; `docker-compose.prod.yml` sets `APP_ENV=production` explicitly. Existing guard tests cover redirect and fail-closed behavior. |
| EF-114 | Sales-order confirmation omitted VAT from its displayed total breakdown | The email showed line totals and grand total but not persisted VAT, so readers could not reconcile subtotal with total. | Fixed in E-010 PR #232: snapshot persisted subtotal/VAT and render both through `CurrencyDisplayService`; fixture checks the displayed breakdown. |
| EF-115 | Critical alert text could alter Markdown and create external links | Alert title and message were interpolated into a Markdown mail body without neutralizing Markdown syntax or URL content, allowing injected links or layout changes. | Fix isolated on `fix/critical-alert-email-markdown-safety`; tests and CI pending. |
| EF-025 | Applicant status email rendered raw enum values and skipped outcome-specific copy | `ApplicationStatusUpdatedMail` passed human-readable stage labels with the same view-data keys as public properties containing raw enum values. Laravel's public-property view data overwrote the labels, so candidates saw values such as `screening`; rejection, offer, and hire-specific text conditions also failed. | Fixed in local commit `6b122579` with distinct label keys and rendering assertions; PR awaits inherited PHPStan blocker. |
| EF-026 | Interview emails rehydrated mutable records in the queue worker | Queued Mailables held Eloquent models, so later reschedules, candidate renames, or posting title changes could make queued mail disagree with event-time data. | Fixed in local commit `fc4e76d4` by capturing candidate-visible fields and Manila display time; tests mutate records after queueing. |
| EF-027 | Credit-note listener referenced a model after conversion to snapshot-only data | The listener's enqueue-failure log still read `$creditNote->id`, leaving an undefined variable and failing PHPStan before PHPUnit. | Fix isolated in draft PR #312; targeted PHPStan passed, full CI is running. |
| EF-028 | Payslip email attached confidential payroll data and linked through the API origin | `PayslipMail` attached the full PDF, and its CTA used `config('app.url')` instead of the SPA origin. | Fixed in local commit `3d859a3d`: attachment removed; authenticated SPA link used. HR and data-protection review required before production. |
| EF-029 | Missing `FRONTEND_URL` fell back to the API `APP_URL` | `config('app.frontend_url')` defaulted to `APP_URL`, which can send email links to the decoupled API origin when `FRONTEND_URL` is missing. | Fix is in draft PR #317: default to `http://localhost`; production must provide `FRONTEND_URL`. First CI run was blocked by EF-118; recheck after its base updates. |
| EF-065 | Email copy hardcoded the company display name | Multiple mail views and portal mail subjects used `Ogami Philippines` directly, so owner-configured identity could not update all messages consistently. | Shared foundation now uses configured sender-name values in email copy and checks views for the old literal; PHPUnit verification pending. |
| EF-118 | Composer audit blocks API checks on vulnerable Symfony HTTP Foundation | PR #317 CI found `symfony/http-foundation` 7.4.14 affected by PKSA-xmwy-rmx5-m7h4 / CVE-2026-108082; this also blocks checks on the current API base. | Draft PR #318 updates only the locked package to 7.4.21. Composer audit reports no advisories locally; CI is queued. |

No code-level fix was applied as part of Phase 0/1.
