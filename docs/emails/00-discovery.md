# Phase 0 — Email discovery

**Snapshot:** 2026-10-20. Static repository inspection only. No email, app command, test, or browser render was run. The working tree was already dirty; mail-related edits were present before this discovery and were not changed.

## Findings and scope

Searches covered `api/app`, `api/routes`, `api/bootstrap`, `api/config`, `api/database`, `api/resources/views`, `spa`, root and API environment examples, Docker Compose files, and scheduler configuration. Search patterns included Laravel mail facades, mailables, `Notification::send`, `notify`, `via`/`toMail`, email views, `mailto:`, frontend auth flows, queue configuration, and scheduled commands.

The repository contains 35 mail/notification implementation files: 34 production implementations and `EmailIntegrationTestMail` (test-only). This is not the count of distinct runtime messages: `UserNotificationMail` is a generic envelope used by many notification type keys, while Laravel notification classes can create messages without a dedicated Mailable. Full runtime count remains unverified because the local database was not queried and code was not executed.

The audit did not find frontend `mailto:` actions or a user-facing send/resend/share-by-email UI in the searched SPA source. The SPA does invoke password-reset endpoints; server-side mail paths are listed below. Exact route coverage and permission enforcement for every resulting screen were not runtime-verified.

## Environment safety gate

Initial inspection found local `.env` and `api/.env` configured with `APP_ENV=local`, `QUEUE_CONNECTION=redis`, `MAIL_MAILER=smtp`, port `587`, and credentials for an AWS SES Mail Manager ingress endpoint. `APP_URL` and `FRONTEND_URL` point to `https://ogamiph.dev`. The initial state could deliver externally. Before continuing, both local env files were changed to `MAIL_MAILER=log` and SMTP host/username/password cleared; the running Horizon container was restarted. Current local mail delivery is therefore isolated to the log driver. No email was sent. Compose still has no Mailpit/MailHog service; the shared-foundation change adds an application-level redirect-or-block safeguard for all non-production environments.

`api/config/mail.php` was absent from the checked-out API config directory even though `.env` configured SMTP. The shared-foundation change adds an explicit config file with a safe `log` default and production SMTP support. The `.env.production.example` describes external SMTP / SES Mail Manager. Do not treat examples as proof of deployed provider configuration.

### Other mail dispatch paths and control points

- `NotificationService` is the shared internal notification dispatcher. It inserts in-app rows, broadcasts through Reverb, and queues generic mail after commit. Email is opt-in per recipient and notification type. Role/permission selection happens at callers; this service does not independently prove row-level RBAC for every linked record.
- `NotificationDigestService` sends one digest per opted-in user. `RunDueScheduledExports` sends attachments to configured recipient arrays. Both use queued mailables, but neither proves delivery/provider acceptance at queue time.
- `AlertEngineService` sends `CriticalAlertEmail` for critical alerts and records bounded retry state. Alert resolution uses `usersWithPermission`; details are in the alert body.
- Direct send calls are synchronous at `Payroll/Jobs/SendPayslipEmailJob`, `CRM/Services/SalesOrderResponseService`, and `Purchasing/Services/SupplierResponseService`. Most explicit Mailable paths use `queue()`.
- Event listeners register mail for invoice finalized, official receipt issued, credit note finalized, customer complaint update, return request update, supplier invoice submitted, sales order confirmed, delivery confirmed, and PO cancelled. Listener registrations live in `AppServiceProvider`.
- `AppServiceProvider` now applies a non-production recipient guard before attaching the inline `ogami-logo@ogami` CID image. The existing shared layout/footer remains the transport-wide presentation shell.
- Laravel's `resources/views/vendor/mail/html/{layout,header,footer}.blade.php` overrides are present. Per-email templates exist under `api/resources/views/emails`. No standalone plain-text Blade view was found; Laravel Markdown/MailMessage generates the alternative part, but actual rendered MIME parts were not inspected.
- There is no committed `api/config/mail.php` and no local mail catcher. Compose has Redis/Horizon and scheduler; no Mailpit/MailHog. Horizon defines a dedicated `mail` queue pool in the already-dirty working tree's `api/config/horizon.php`, but older jobs may remain on default queue. Verify deploy service composition before relying on that config.
- Queue uses Redis and failed-job database UUIDs. Horizon and scheduler are configured in Compose. `routes/console.php` schedules production summaries, notification digest, exports, AR dunning, alert retry, payroll email reconciliation, and other operational jobs. Exact worker attempts/backoff for each message were not exhaustively checked in this phase.

## Cross-cutting quality and risk findings

1. **No non-production email interception:** local configuration points to an authenticated external SMTP ingress with credentials. No Mailpit service, forced redirect, staging subject prefix, or test-only transport safeguard was found in compose/config. This is the hard stop for further dynamic verification.
2. **Placeholder company values in source fallback:** `EmailBrandingService` falls back to a placeholder address, phone, TIN, VAT status, certification, legal name, and sales mailbox when settings are absent. Some values resemble fabricated company facts. The settings table and PDF branding settings exist, but actual DB values were not read. Do not send any branded email until real values are confirmed and these fallback paths are handled.
3. **Plaintext temporary credentials:** four welcome/reset notification implementations accept or expose temporary passwords. Reachability and intended provisioning flow need tracing; if active, this is a security finding and separate PR, not a template-only change.
4. **Synchronous sends:** payslip, supplier PO decision, and customer sales-order decision sends execute in request/job flow. Payslip includes an attachment and personal data. Failure can block work; determine whether caller retries can duplicate delivery.
5. **Recipient authorization:** external documents mostly target customer/vendor record addresses or portal users. Internal generic mail uses explicit notification preferences, but permissions are caller-resolved and links may expose records after login. Some selectors include fallback addresses. Verify active-user state, object visibility, and duplicates per flow.
6. **Generic notification flood/sensitivity:** every opted-in notification type can reuse `UserNotificationMail`; this includes approvals, exceptions, HR, payroll-ready, and operations. Sensitive detail may be placed in notification message text. Digest exists separately. Category opt-in and preference defaults need a type-by-type sensitivity check.
7. **Links:** most generic links are passed from business callers; auth/portal flows construct links elsewhere. The shared brand header previously linked to Laravel's `app.url`; the foundation now points it at `FRONTEND_URL`. Per-email SPA route existence, login-return behavior, API/SPA separation, and signed-link semantics remain unverified.
8. **Visual and HTML status:** no emails were rendered or visually inspected because local mail delivery is unsafe and the browser-render phase is explicitly later. Current appearance is therefore ungraded; no Outlook/Gmail/Apple Mail claim is made. Template-family output is not fully known without rendering.
9. **Audit/failure observability:** app has `EmailDeliveryFailureNotifier`, logs around some dispatches, alert retry records, queue failed jobs, and scheduled export failure notifications. No dedicated email log table/Email Center was found in the inspected paths. Full send status/provider message-id/bounce tracking is not evident.
10. **Other channels:** in-app notifications are persisted and broadcast over Reverb. The app has no email settings/preferences UI found in the SPA source search; preferences are stored in `notification_preferences` and API controllers. No SMS sender was found in the mail-focused search.

## Foundation facts

- Existing company/PDF settings live in the `settings` table: `company.*`, `pdf.footer_disclaimer`, PDF accent/terms, and `email.brand_name`. A read-only presence check found legal name, address, phone, general/sales email, TIN, VAT status, certification, public URL, and display name populated. The configured sales inbox and VAT status match the old source fallback strings and need owner verification. `company.logo_path` is empty, but the API contains bundled logo assets. Values were not copied into this report.
- The SPA base URL is `FRONTEND_URL`; app config falls back to `APP_URL`. Local values point to `ogamiph.dev`. A single link helper/route validator was not found in this pass.
- PHP app timezone is set in `api/config/app.php`; exact value and display conversion in every email remain unverified. Do not infer Asia/Manila correctness from the prompt.
- Environment examples describe SES SMTP / SES Mail Manager. From defaults are configured from `MAIL_FROM_ADDRESS` and `MAIL_FROM_NAME`; no explicit shared Reply-To policy was identified in repository config. The owner reported DKIM setup succeeded for `ogamiph.dev` in AWS Asia Pacific (Singapore); this report does not independently verify DNS/provider state. SPF, DMARC, bounce webhooks, suppression lists, and provider reputation cannot be verified from source.
- Horizon, Redis queues, failed-job persistence, and scheduler are present. Queue depth/failed job metrics have a health/operations surface; mail delivery success rate/provider event tracking was not found.
