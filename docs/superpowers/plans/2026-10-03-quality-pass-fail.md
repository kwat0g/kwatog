# Quality PASS / FAIL per Item Implementation Record

**Goal:** Each specification/checklist parameter has PASS and FAIL buttons; repeated sample readings do not duplicate the questions.

**Implementation:** Group by immutable specification item or full parameter identity. Save decisions and failure problems separately from measured evidence. Allow partial drafts and explicit PASS all remaining without overwriting failed checks. Submit requires all items answered, derives the overall verdict, rechecks saved PASS decisions against current evidence, and keeps the existing checker/NCR/certificate gates. The former public whole-inspection result endpoint and panel were removed. Legacy completion uses checklist decisions whenever they exist.

**Validation:** Focused backend and frontend tests exercise all stages, grouping, partial drafts, blank problems, foreign/duplicate items, bypass prevention, contradictory readings, checker independence and certificate refusal. Live browser checks use the five labeled sample drafts at desktop 1440px and mobile 390px: five decision rows each, failure-only problem fields, bulk PASS preserves failures, 44px buttons and no horizontal overflow. The additive checklist migration was applied to the current local runtime. No commit or deployment is required.

**Results:** 63 affected backend tests (237 assertions), 37 frontend tests, production build, targeted ESLint/PHPStan and diff checks passed. Focused checklist tests and reverse sample insertion order passed after canonical sorting. Independent review findings were fixed with regression checks. Temporary test configuration was removed.

**Measurement replacement:** Removed both legacy measurement editors, sample-count forms, numeric controls, measurement draft state and save APIs from the SPA. Removed unused measurement components and their implementation-specific tests. Inspection details now shows record metadata and links above the checklist without a dropdown. Five stage-specific regression cases verify its position and absence of entry fields, then exercise FAIL problem entry and bulk PASS submission readiness. Backend evidence and certificate checks remain intact.

**Replacement verification:** Ten focused frontend tests passed, including all five stages with Details expanded and no measurement inputs. Live desktop/mobile checks passed for all five existing samples: no hidden inputs, failure-only problem entry, bulk PASS preserves failures, no horizontal overflow. Targeted ESLint and diff checks passed. Read-only planned sample guidance remains visible.

**Layout and workload reduction:** Added search and All checks/Needs attention for more than twelve checks, compact decision rows, and sticky Save/Submit controls. Filters do not change the scope of bulk PASS or submitted decisions. A focused keyboard regression proves focus advances when passed rows disappear, with the attention filter as fallback. Twelve focused frontend tests passed. Browser verification covered all five stages and a read-only 100-check preview at 1440px and 390px, including search, filtering, preserved failures, visible sticky actions and zero runtime/server errors. Sample drafts were not saved or submitted.

**Context restoration:** Restored AQL limits, distinct sample/measurement defect totals, both start and completion dates, product/item navigation, record flow, checker history and SPC summaries. Saved measurement history is read-only. Record flow now precedes the details; SPC appears directly beneath linked records in the right column. The main column contains details and the checklist. A regression covers retained content and section order. Thirteen focused frontend tests pass. Browser verification uses read-only draft previews because users may edit the real demonstration records during checks.
