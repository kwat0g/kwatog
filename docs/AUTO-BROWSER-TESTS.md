# OGAMI ERP — Autonomous Browser Test Suite & RBAC/SoD Audit

> Generated by a Principal-QA / DevSecOps / RBAC pass against the **live** stack
> on branch `feat/OGAMI-104-idempotency`. Every "Result" line below was produced
> by executing the test against `http://localhost` — not inferred from code.
>
> **Companion files**
> - `evals/contracts/*.json` — convergence-harness task contracts for `auto-browser`
> - `scripts/qa/rbac-live.sh` — the runnable curl harness that produced the results here
>
> **Tooling reality check.** The target executor is
> [`LvcidPsyche/auto-browser`](https://github.com/LvcidPsyche/auto-browser), which is
> **not** a natural-language step DSL. It is a browser control plane driven by
> **JSON over REST** (`POST /sessions`, `GET /sessions/<id>/observe`) or **MCP tool
> calls** (`POST /mcp/tools/call` → `{name, arguments}`). Auth = *manual login saved
> as a reusable named profile*, then reused. Assertions = reading `/observe`
> (screenshots / DOM summary / OCR) or the convergence harness's task-contract
> verification (`--mock-final-url` / `--mock-final-text`). Part 3 is written to that
> reality. Because `auto-browser` was not installed in this environment, the suite
> was *also* executed directly against the API to produce real findings — see
> `scripts/qa/rbac-live.sh`.

## 1.2 The three chains (verified state machines)

```
CHAIN 1 — ORDER TO CASH
  SO(draft→confirmed) → MRP plan → WO(planned→confirmed→in_progress→completed→closed)
  → output (mold shots+, scrap%) → outgoing inspection(draft→in_progress→passed|failed)
  → [failed → NCR auto-open] → Delivery → Invoice(AR) → Collection → GL

CHAIN 2 — PROCURE TO PAY
  PR(draft→pending→approved→converted) → PO(draft→pending_approval→approved→sent→received)
  → GRN(pending_qc→accepted) [gated: incoming inspection=passed] → weighted-avg-cost recompute
  → Bill(AP) → Payment → GL

CHAIN 3 — HIRE TO RETIRE
  Hire → Shift assign → Biometric CSV → DTR → Leave(pending_dept→pending_hr→approved)
  + OT(pending→approved) → Payroll(draft→processing→approved→finalized→disbursed)
  → Payslip → Bank file → GL → Separation → Clearance → Final pay
```

# PART 3 — `auto-browser` Execution Scripts

## 3.0 One-time setup (per role profile)

```
# Bootstrap each role as a reusable auth profile (manual-login-once model)
for (profile, email) in the table in §Environment:
  browser.create_session {name: profile, start_url: "http://localhost/login"}
  browser.act "Type {email} in email, 'password' in password, click Sign in;
               wait for the dashboard to load."
  browser.save_profile {session_id, profile_name: profile}
# Portals log in at /portal/supplier/login and /portal/customer/login.
```

Each test = `OPEN[P_x]` (create_session from a saved profile, already authed) →
`act` directives → **ASSERT** via `GET /sessions/<id>/observe`. For unattended CI,
the terminal assertion of each test is mirrored as a convergence task-contract under
`evals/contracts/` (see §3.2).

> The MCP/REST primitives behind every `act`/`observe`:
> ```bash
> curl -s http://127.0.0.1:8000/sessions -X POST -H 'content-type: application/json' \
>   -d '{"name":"t1","start_url":"http://localhost/login"}' | jq        # -> {id}
> curl -s http://127.0.0.1:8000/mcp/tools/call -X POST -H 'content-type: application/json' \
>   -d '{"name":"browser.act","arguments":{"session_id":"<id>","instruction":"<directive>"}}'
> curl -s http://127.0.0.1:8000/sessions/<id>/observe | jq              # -> assertion surface
> ```

| ID | Severity | Title | Root cause & fix | Status |
|---|---|---|---|---|
| **DEFECT-1** | **High** | OT self-approval guard was dead code | `OvertimeService.php:158` read `$ot->employee?->user_id`, but `employees` has **no `user_id` column** (link is `users.employee_id → employees.id` via `Employee::user()` HasOne). `$submitterId` was always `null`, so the check never fired → depthead self-approved own OT (HTTP 200). **Fix:** `$submitterId = $ot->employee?->user?->id;` + `OvertimeController::approve/reject` now surface the `RuntimeException` as **422** (was leaking 500). | ✅ FIXED — re-test: self-approve → 422, other approver → 200. |
| **DEFECT-2** | Medium | PO vendor SoD (Guard C) was dormant | `assertVendorSod()` short-circuits when `vendors.created_by` is absent — column never existed. **Fix:** migration `0222_add_created_by_to_vendors`, added to Vendor `$fillable`, `VendorService::create()` stamps `created_by = Auth::id()`. Guard now fires. | ✅ FIXED — tinker + feature test: creator approving own-vendor PO → 403; override lifts it. |
| **DEFECT-3** | Low | Internal SPA stack 500'd on a portal token | Real chokepoint was **`SessionTimeout` middleware** (not the controller): it wrote `last_activity` on the resolved principal; a `SupplierPortalUser` (no such column) → SQL 500. **Fix:** `SessionTimeout` + `AuthUserController` now reject any non-`User` principal with a clean **401**. | ✅ FIXED — supplier token → `/auth/user` 401, own portal still 200, admin still 200. |
| Doc-fix | — | SoD guards surface as **422**, not 403 | Guards A/B/D/E return 422 (controllers map abort/RuntimeException → validation error); Guard C returns 403 (`abort(403)`). Corrected throughout. | ✅ |
